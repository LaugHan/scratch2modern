# H-Net：让模型自己学分词

论文：[Dynamic Chunking for End-to-End Hierarchical Sequence Modeling](https://arxiv.org/abs/2507.07955)，Sukjun Hwang、Brandon Wang、Albert Gu，2025 年 7 月，ICLR 2026。Albert Gu 是 Mamba 的作者之一。代码：[goombalab/hnet](https://github.com/goombalab/hnet)。

## 问题

现在的语言模型都是三段：分词器把文本切成 token，模型处理 token，最后再拼回文本。分词器是单独训练的，规则是人定的（BPE，1.05），不参与模型的训练。这带来几个毛病：

- 对错别字、大小写这类字符级的改动很脆弱。"Hello" 和 "hello" 是两个毫不相干的 token。
- 在不靠空格分词的数据上切得不好，比如中文、代码、DNA。
- 换一个分词器，整个模型的口径都变了，loss 也没法直接比（1.05 因此改用 bpb）。

H-Net 的想法是**去掉分词器**：模型直接读字节，自己学怎么把字节分成块，分块的方式和模型一起端到端训练。

## 是什么

### 整体：一个 U 形

```
字节 ──► 编码器（小，读每个字节）──► 分块：只留下一部分位置 ──► 主网络（大，只处理块）
              │                                                      │
              └──── 残差（过一个线性层）──────► + ◄── 还原到每个字节 ◄───┘
                                               │
                                        解码器（小）──► 预测下一个字节
```

这个形状来自图像分割里的 U-Net：先降低分辨率，在低分辨率上做主要的计算，再放大回来，中间用跳连把细节补回去。H-Net 在序列上做同样的事。

- **编码器、解码器**：各 4 层，用的是 Mamba-2。Mamba 是一种状态空间模型（SSM），可以把它理解成一种能并行训练的 RNN，计算量随长度线性增长。字节序列很长（GPT-2 的一个 token 平均 4.6 个字节，2.01），所以两头用便宜的层。论文还发现，即使输入是 BPE token，这个位置上 Mamba 层也比 Transformer 层好。
- **主网络**：Transformer，参数大部分在这里。它处理的是压缩后的块，每块平均约 5 个字节，长度和一个 BPE token 差不多。
- **可以嵌套**：主网络本身也可以是一个 H-Net，就成了两级：字节 → 小块 → 大块。

论文里的写法：M 是 Mamba-2 层，T 是 Transformer 层，数字是层数。

| | 一级 | 两级 |
|---|---|---|
| Large | M4 + T22 + M4 | M4 + T1M4 + T26 + M4T1 + M4 |
| XL | M4 + T24 + M4 | M4 + T1M4 + T27 + M4T1 + M4 |

### 分块是怎么学出来的

**1. 哪里该切（routing）。** 对相邻两个位置的向量分别做一次投影，q_t = W_q x_t，k_t = W_k x_t，看它们像不像：

  p_t = ½ · (1 − cos(q_t, k_{t−1}))

前后两个字节的表示越不像，越可能是一个新块的开始。p_t ≥ 0.5 就切一刀，第一个位置总是切。这个判断只用到当前和前一个位置，是因果的，可以用来逐字节生成。

**2. 下采样。** 只留下切开处的那些向量，其余丢掉，送进主网络。论文也试过平均、取最大值、交叉注意力，直接挑最简单，效果也好。

**3. 还原（dechunk）。** 主网络对每个块输出一个向量，再复制给这个块覆盖的每个字节。这一步本来不可导：切还是不切是离散的，梯度传不回 routing。论文用了两个办法：

- **平滑**：用指数移动平均（EMA）把相邻块的输出混一混：

  z̄_t = P_t · ẑ_t + (1 − P_t) · z̄_{t−1}

  边界很确定时（P ≈ 1），这块保持独立；不太确定时（P ≈ 0.5），就混进前一块。这样"切错"的代价变成连续的，梯度能传回去。去掉平滑，压缩率会剧烈波动，效果也明显变差。
- **直通估计（STE，straight-through estimator）**：输出乘上置信度 c_t，c_t 在切开处是 p_t，在没切处是 1 − p_t。前向时把这个乘数当成 1，不改变数值；反向时梯度照着 c_t 走，从而推动 routing 变得更确定。

**4. 切多碎（ratio loss）。** 如果不管，模型可能每个字节都切，或者一刀都不切。所以加一个辅助 loss，让它大约每 N 个字节切一刀：

  L_ratio = N / (N − 1) · ((N − 1) · F · G + (1 − F) · (1 − G))

F 是实际切开的比例（不可导），G 是 p_t 的平均（可导）。F = G = 1/N 时，L_ratio 取最小值 1。总 loss 是预测下一个字节的 loss 加 0.03 × L_ratio。一级模型的 N 是 6，实际学出来平均每块 4.8 个字节；两级模型每级 N 都是 3。

### 几个细节

- **每个子网络的结尾都有一层 RMSNorm**（编码器、主网络、解码器），让残差和主路的大小差不多。这正是 2.01 发现我们缺的那个输出层前的 norm。
- **残差上加一个线性层，初始化接近 0**，只加在残差这一路上。两路都加反而更差。
- **外层的学习率比内层高**，论文说这样边界学得更快。
- **宽度从外到内不减小**。变宽时补一个可学的向量，变窄时直接截掉多出来的维度，不加额外的矩阵。

## 为什么能比 BPE 好

- **分块和模型一起训练**：BPE 只按字节对出现的频率合并，H-Net 按"这里切开对预测有没有帮助"来切。
- **按内容决定算多少**：难的地方切得碎，主网络就在这里多算几次；容易的地方块大，就少算几次。BPE 的切法和内容难不难无关。
- **主网络看到的是有意义的单位**：论文说，没有任何规则或监督，模型也学出了有意义的切法。具体切成什么样，我还没细看论文里的可视化，留给下面"以后可以做"的第一项自己画出来看。

## 结果

数据和我们的 2.01 一样，是 FineWeb-Edu，用了 1000 亿 token 的子集。字节模型每条序列 8192 个字节，BPE Transformer 每条 1792 个 GPT-2 token，batch 都是 256。各模型每个 batch 的字节数和每个字节的计算量都对齐。因为分词器不同，这里比较的是 bpb，这正是 bpb 该用的场合（1.05）。

| 模型 | Large bpb | Large 零样本平均 | XL bpb | XL 零样本平均 |
|---|---|---|---|---|
| BPE Transformer | 0.756 | 53.3 | 0.730 | 55.5 |
| SpaceByte++（按空格切的字节模型） | 0.760 | 53.6 | 0.733 | 56.1 |
| H-Net 一级 | 0.755 | 53.6 | 0.728 | 56.2 |
| H-Net 两级 | **0.743** | **55.5** | **0.715** | **58.2** |

- **一级只和 BPE 差不多，两级才明显更好。** 两级的 Large 和大一号的 XL Transformer 差不多。
- **训练早期它不如 BPE。** 两级 H-Net 大约要训练到 300 亿字节才追上 BPE Transformer，一级要到 1000 亿字节左右。
- **对字符级扰动更鲁棒。** 在 HellaSwag 上做大小写随机、删字符、重复字符等扰动，用论文附录定义的鲁棒性得分，XL 规模上 Transformer 是 22.2，H-Net 两级是 42.8。不过其他字节模型也在 35 到 38 左右，所以**鲁棒性主要来自"读字节"本身**，H-Net 只是在这之上又好了一些。
- **在中文、代码、DNA 上优势更大。**
  - 中文验证集 bpb：Transformer 0.740，H-Net 两级 0.703。这里 BPE 基线换成了 Llama 3 的分词器，因为 GPT-2 的分词器切中文太碎。
  - 代码：0.338 对 0.316。
  - DNA：达到同样的困惑度，用的数据约是原来的 1/3.6。

## 局限

- 规模最大只到 16 亿参数、约 1000 亿 token。
- 超参数多：每级的学习率、ratio loss 的系数、目标压缩率 N。
- 字节序列长，块的长度又不固定，训练和推理的工程实现都比普通 Transformer 麻烦，论文对效率只做了部分分析。
- 跟进的工作不多。[H-Net++](https://arxiv.org/abs/2508.05628) 把它用在了波斯语上。

## 和我们的关系

- **分词器（1.05）**：我们在那里训练过 BPE，也因此改用 bpb。H-Net 是"把分词也交给模型学"的一种答案。
- **输出层前的 norm（2.01、2.03）**：H-Net 在每个子网络结尾都放了 RMSNorm，并且明确说是为了平衡残差和主路的大小。
- **数据**：和第二章用的是同一个数据集 FineWeb-Edu，以后要做小实验可以直接接上。
- **规模的提醒**：它的优势要训练到几百亿字节才出现，我们一小时只能训练约 5 亿 token（约 25 亿字节）。如果自己做小号 H-Net，很可能只能看到"还没追上"的阶段。
