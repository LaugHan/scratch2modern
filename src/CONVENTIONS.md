# 规范

这里只管怎么写、怎么放。实验怎么设定，每章的 plan.md 里单独说。

## 一、项目怎么组织

```
README.md               # 整条路线：每节一句话，按顺序读
TODO.md                 # 全项目的待办（以后再做的实验、没解决的问题）
data/                   # 原始数据和分词后的数据，各章共用；派生出的文件要写明是哪个脚本生成的
src/
├── CONVENTIONS.md      # 本文件
├── ch1/
│   ├── 1.01_microgpt/
│   └── ...
└── ch2/
    ├── plan.md
    ├── common.py       # 这一章不变的部分：数据、评估、训练循环、日志、生成
    └── 2.01_baseline/
        ├── train.py    # 这一节的模型和配置
        ├── sweep.sh    # 这一节跑过的全部命令
        ├── plot.py     # 读 out/，画图，打印 notes 里用到的每一个数
        └── notes.md
out/
└── ch2/2.01_baseline/<run>/   # log.csv、final.csv、samples.txt
```

原则：

- **一节一个目录，一个目录只回答一个问题。** 顺带冒出来的问题放进 `analysis/`，自带一份 notes；不值得单独回答的，记进 TODO.md。
- **固定四个文件：train.py、sweep.sh、plot.py、notes.md。** 别的文件要有理由才加。
- **out/ 和 notes 对得上。** notes 里没用到的 run 删掉，不留"可能有用"的结果。
- **从命令到数字可以复现。** 跑 sweep.sh 得到 out/，跑 plot.py 得到 notes 里的图和数。
- **一节做完提交一次 git**，提交信息写这一节的结论。服务器上的仓库是唯一的正本。
- **第一章保持原样。** 只是挪进了 `ch1/`，代码里读写的路径还是旧的（`data/`、`out/<节>/`），重跑哪一节时再改那一节。

## 二、代码怎么写

### 基调

- **读者是来学东西的人。** 打开 train.py，从上往下读一遍，就知道这一节的模型长什么样、和上一节差在哪。
- **相邻两节 diff 一下，就是这一节学的东西。** diff 里不应该出现和这一节无关的改动。

第一章的代码读起来累，主要有这几个原因：

- 每节都把数据、评估、计时、日志、生成全写一遍，真正要看的那几行淹没在里面。
- 注释中英混杂，很多注释接在长代码行的末尾，一行超过 150 个字符。
- 变体的写法不统一：有的放进 `optimizers/` 这样的子目录，并且在相邻两节之间复制；有的用开关。
- 很多不短的逻辑用 lambda 写在一行里。
- 能用 PyTorch 自带的地方还在手写，比如 softmax、cross entropy。

第二章按下面的规矩来写。

### 规矩

1. **每节只写变的部分。** 第二章的训练方式不变，所以把数据、评估、训练循环、日志、生成放进 `ch2/common.py`，这一章内不改。train.py 只写配置、模型、参数怎么分给优化器，目标是 100 行左右。common.py 真要改的话，在 plan.md 里记一笔，并且重跑基线。
   - common.py 是一层抽象，但只藏前面章节已经讲清楚的东西。写成几个普通函数（读数据、算 bpb、训练循环、生成），从上往下读得懂；不写类层级、回调、注册表这类框架式的东西。
   - train.py 显式调用这些函数。读者想看训练循环，打开 common.py 就是那 30 行，不用跳来跳去。
   - 判断一样东西放不放进 common.py：它在这一章的所有节里都一模一样，而且不是任何一节要比的对象。
2. **模型用 `nn.Module`**，按 Attention、MLP、Block、GPT 拆开，这一章就是在换这些零件。能用 PyTorch 自带的就用，例如 `nn.Linear(bias=False)`、`F.rms_norm`、`F.scaled_dot_product_attention`、`F.cross_entropy`。只有手写本身就是这一节要学的东西时才手写，例如 RoPE、MLA。
3. **要比的变体并排写在同一个文件里**，用一个字典来选。到了下一节，只留下胜出的那个，其余的删掉。
4. **配置是一个 dataclass。** 命令行用 `key=value` 覆盖默认值。run 的名字只由和默认值不同的字段拼出来，比如 `mlp=swiglu_s43`。
5. **注释用中文，说为什么，不说做什么。**
   - 来自前面某节结论的选择，标注出处，例如 `# 不加 weight decay：L2 的写法会让训练失败（1.10）`。
   - 张量形状只在形状变化的地方注。
   - 注释写在代码的上一行，不接在行尾，除非很短。
   - import 不加注释。
6. **一行不超过 100 个字符。** 超过一行的逻辑写成 `def`，不用 lambda。
7. **没有死代码。** 每个开关都要对应 notes 里的一个实验。不写防御性检查，只在真会出错的地方 assert，比如参数量对齐。
8. **命名沿用 GPT-2 和 nanoGPT 的习惯**（`n_layer`、`n_embd`、`n_head`、`wte`、`lm_head`），和第一章保持一致。

## 三、notes 写什么

### 为什么要写 notes

notes 是这一节的实验记录，也是这一节结论唯一的出处。页面（docs/）从 notes 改写，用词和顺序可以不同，但数字只从 notes 来。读 notes 的是一个月后的我们，和对照着代码读的人。

### 回答什么

开头一句话提出这一节的问题，结尾的结论直接回答它。中间只放回答这个问题所需要的东西。

### 结构

1. **问题**：一两句话。
2. **是什么、为什么**：要比的几种做法各是什么，各自想解决什么问题。只写到能看懂实验的程度，完整的讲解放到页面上。
3. **怎么比**：只写这一节特有的设定，和基线相同的部分一句带过。
4. **结果**：一张图或一张表。
   - 图里只放编号和英文标签，解释写在图外的说明里。
5. **结论**：几条要点。
   - 每条先说结论再说理由，并且带上数字。
   - 差距小于 seed 的波动时，写"打平"。
6. **和大模型的关系**（可选）：我们的结论在真实模型里成不成立，以及这个玩具模型的局限。

### 规矩

- **notes 里的每一个数，plot.py 都能打印出来。** 重跑以后直接改数字，不保留旧的值。
- **没验证过的解释标明是猜测。** 验证过的才写成结论。
- **小众概念第一次出现时先解释。**
- **失败的尝试只在有信息量时记**，一两句话。被放弃的 run 不记。
- **长度跟着结论走**，不为了完整而写。

## 四、其他需要统一的

- **指标**：一律用验证集的 bits per byte（bpb），验证集固定为同一份。
- **时间**：只算训练，不算评估。
- **seed**：42、43、44。
- **日志格式**：
  - `log.csv` 的列在一章之内固定。
  - `final.csv` 只有一行，放最终结果。
- **图的风格**：同一章用同一套颜色顺序和字号，每张图都有标题和坐标轴单位。
- **TODO.md** 移到项目根目录，各章共用。
